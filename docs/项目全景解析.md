## 一、项目概述

PaperWise 是一个**多 Agent 协作的学术论文智能解读系统**。输入一篇 PDF 论文，自动完成：

- 解析论文（文本 / 图表 / 表格 / 公式 / 参考文献）；
- 生成深度解读报告（Markdown，7 个章节）；
- 生成学术汇报 PPT（PPTX，含图表）；
- 对话式深度问答（有记忆、跨轮上下文）；
- 主动论文推荐（记忆驱动的兴趣画像）；
- 质量审核闭环（对抗式审查 + revise-until-pass）。

核心理念来自《深入理解 AI Agent：设计原理与工程实践》：

```text
Agent = Model + Harness + Environment
```

## 五、核心执行链路

### 5.1 端到端论文分析（pipeline）

```text
PDF 上传/arXiv 链接
  → PDFParser.parse()  → text.md / metadata.json / figures / tables / formulas / references
  → 记忆注入（论文主题 → interest_signal，供主动推荐）
  → 编排器 run_paper_analysis()
      → Analyst（写 analysis/*.md 分析）
      → ReportWriter（写 report/sections/*.md + report/report.md）
      → Reviewer（对抗式审查 → findings.md）
      → 若未通过 → RevisionWriter 修订 → 回到 Reviewer（≤3 轮）
  → 最终报告 + 可选 PPT
```

### 5.2 对话式问答（chat）

```text
用户消息 → AgentSession.chat()
  → 注入记忆上下文（to_context_string）
  → ReAct 循环：LLM 决定「回答」或「调用工具」
  → 工具执行（经 Harness 安全检查）
  → 回答后 → _auto_remember（LLM 提取记忆）+ KB 关联检索
  → 持久化 Session
```

### 5.3 主动推荐（recommend）

```text
记忆（声明兴趣 + 论文信号 + 对话信号）
  → build_interest_profile()（加权聚合 + 新鲜度衰减）
  → arXiv API 拉取近期论文
  → score_paper() 相关度评分
  → 排序 + 缓存 → 前端横幅 / 注入 Agent 上下文
```

## 六、关键模块详解

### 6.1 `core/agent.py` — 增强 ReAct 循环

核心是 `Agent.run(task)`，每次迭代：`pre_llm → call_llm → post_llm → 解析响应 → post_tool → check_exit`。

增强特性（对比基础 ReAct）：

- **Budget-Aware**：剩余预算 >80% 时注入「停止探索、立即产出报告」提示；
- **Plan-then-Execute**：任务开头要求先写 `analysis/plan.md`；
- **过早终止检测**：连续 N 次纯文本响应触发 `_verify_completion()`（Proposer-Reviewer），未完成则强制继续；
- **流式思考**：思考文本按 0.5s/自然断点缓冲推送；
- **7 种退出条件**：max_steps / token_budget / circuit_breaker / time_budget / consecutive_errors / 正常完成 / 过早终止判定；
- **轨迹持久化**：每次运行保存 `workspace/.trajectories/traj_*.json`。

### 6.2 `core/session.py` — 对话式会话

`AgentSession` 与 `Agent` 的区别在于：**跨轮保留上下文**（不每次重建），具备：

- 记忆注入（每轮 `to_context_string`）；
- 上传论文 → 解析 → 注入 `<paper_loaded>` 系统消息；
- 后台异步：注入 Sidecar 审查 + KB 索引（RAPTOR/GraphRAG/多模态）；
- 论文主题 → 写入记忆（`interest_signal`），驱动主动推荐；
- 持久化到 SQLite，服务重启可恢复。

### 6.3 `harness/` — 护栏工程

| 模块 | 职责 |
|------|------|
| `harness.py` | pre/post-LLM、pre/post-tool 钩子，熔断器，退出条件 |
| `context.py` | 5 层上下文压缩（工具截断→噪声删除→微压缩→归档摘要→LLM 全量压缩） |
| `constraints.py` | 输入/执行/输出三层护栏 |
| `security.py` | 注入/命令/路径/密钥/系统提示泄露检测 |
| `sidecar.py` | 注入 Sidecar LLM 审查（论文内容视为数据） |
| `status_bar.py` | 状态栏 XML + 循环检测 |
| `correction.py` | 重试 + 指数退避 + 熔断器 |
| `verification.py` | 输出验证（文件存在/JSON 合法/报告结构） |

### 6.4 `tools/` — 17 个工具（五类）

1. **感知**：read_file / grep / glob
2. **执行**：write_file / edit_file / code_interpreter / bash
3. **Skill**：skill_list / skill_load / discover
4. **协作**：spawn_subagent / send_message / set_timer / monitor_shell
5. **沟通**：ask_user / notify_user

外加 `request_file_access`（用户授权文件访问）与 `receive_message`（消息接收）。

工具基类 `BaseTool` 实现了分级路径沙箱（工作目录内直接读写；外部路径需授权或只读白名单）。

### 6.5 `memory/` — 记忆与 RAG

**UserMemory**：Advanced JSON Cards（5 类：preference/fact/relationship/experience/knowledge），LLM 从对话提取，支持去重合并、冲突检测、周期整合。

**KnowledgeBase**：完整 RAG 管线：

- Dense（sentence-transformers → API embedding → TF-IDF 降级）
- Sparse（BM25）
- Hybrid（RRF 融合，稠密 0.6 / 稀疏 0.4）
- Rerank（LLM-as-Reranker 交叉编码）
- HyDE（假设文档）
- RAPTOR（层次摘要树）
- GraphRAG（实体/关系图谱）
- 多模态（图表/表格索引）
- Agentic RAG（`get_search_tool_description` 暴露给 Agent）

### 6.6 `recommender.py` — 主动推荐

- `extract_paper_topics()`：从论文标题/摘要/关键词提取主题短语；
- `remember_paper()`：把论文主题写入记忆（`interest_signal`）；
- `build_interest_profile()`：聚合「声明/论文/对话」三类信号，30 天半衰期衰减；
- `score_paper()`：整词/短语命中权重高于部分 token 命中，含泛化词停用；
- 数据源：arXiv API → arXiv 列表页 → Semantic Scholar 三级回退。

### 6.7 `agents/` — 多 Agent 编排

`AgentOrchestrator`（Manager+Worker）：子 Agent 不共享上下文，通过文件系统交换产物。

`PaperAnalysisPipeline` 定义 5 类规格：Analyst / ReportWriter / Reviewer / AdversarialReviewer / Revision。

`run_paper_analysis()` 实现 **revise-until-pass** 闭环：审核发现 critical/major 问题 → 修订 → 再审（≤3 轮），否则标记 `needs_manual_review`。

### 6.8 `evaluation/` — 评估体系

- `RubricEvaluator`：4 维评分（accuracy/completeness/insight_depth/evidence_quality）；
- `HallucinationDetector`：幻觉检测（critical/major/minor）；
- `PassKEvaluator`：Pass@k（至少一次成功）/ Pass^k（连续全成功）；
- `AblationTester`：逐组件消融。

> 两者现均通过 `Settings.build_judge_llm()` 使用**异源 Judge**，避免与主模型同源包庇。

### 6.9 `evolution.py` — 持续进化

`EvolutionEngine` 把失败轨迹聚合为模式，按「知识 → 指令 → 程序 → 参数」四层固化（写入知识库 / Skills 文件 / Harness）。

### 6.10 `mcp/` — MCP 协议

`MCPServer`（stdio JSON-RPC）对外暴露工具/资源/提示模板；`MCPClient` 连接外部 MCP 服务器并注册为本地工具。

## 七、配置系统

`config/settings.py`（pydantic-settings）从 `.env` 加载，关键项：

- 主模型：`llm_provider` / `default_model` + 各 provider 的 api_key/base_url；
- **异源 Judge**：`judge_provider` / `judge_model` / `judge_api_key` / `judge_base_url`，独立于主模型，可单独换源；
- 工作区 / Agent 预算 / 温度 / 熔断阈值等。

## 八、前端

`web/static/`：单页聊天界面（`index.html` + `app.js` + `style.css`），含会话侧栏、论文上传、推荐横幅、记忆/报告/章节编辑面板、PPT 生成、评估 Dashboard（`dashboard.html`）。

## 九、测试与测评

- `tests/`：单元测试（core/harness/tools/memory/parsers/agents/api/integration）+ `run_agent_tests.py`；
- `测评/`：真实论文测评（测试设计 / 测试结果 / 金标 / 消融实验）与复现脚本。

## 十、近期变更（相对历史文档的差异）

## 十一、已知问题与改进方向

- 报告生成在长论文上仍不稳定（LLM 随机性 + 步骤预算，已加确定性组装兜底但非根治）；
- 幻觉/Rubric 的异源 Judge 已留好配置位，但尚未切换到真正异源模型；
- RAPTOR/GraphRAG 索引未持久化（每次重建）；
- 推荐评分对短词/缩略词的精确率仍可进一步优化。
